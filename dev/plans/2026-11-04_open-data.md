# Ouvrir les données

État : proposition de Claude du 2026-11-04, à valider par Lou ; rien n'est commencé. Point « Ouvrir les données » de `ROADMAP.md`. Ce qui est décidé, et pourquoi, est dans `dev/decisions.md` (« Ouverture des données ») : ce fichier ne dit que comment le faire.

## Quand

Après la preuve d'identité avec l'ancien, comparé à part, avant les essais : les testeurs et les gestionnaires voient l'ouverture elle-même et donnent leur aval, derrière le VPN et un mot de passe d'accès (`dev/plans/2026-10-26_deployment.md`).

## Ce qui change

**1. La règle** (`BdohRightVoter::canDownload`). Une chronique visible se télécharge sans compte ; une chronique cachée demande les droits d'aujourd'hui, inchangés. Une demande qui mêle les deux répond 403 sans le droit, comme aujourd'hui.

**2. L'export sans compte.** Aujourd'hui, le formulaire met une tâche en file (`JobManager::enqueueExport`, qui demande un `Utilisateur`), et le résultat part en pièce jointe d'un courriel (`AbstractExportCommand`, `--send-to`). Sans compte, il n'y a pas d'adresse. Proposition :

- Le formulaire reste le même : dates, type, pas, format, fuseau. Les fichiers exportés ne changent pas (mêmes formats).
- L'export passe toujours par la file : une grosse chronique dépasse le délai d'une page (`volumes.py` dira de combien), et la file protège le serveur, une tâche à la fois.
- Le fichier va dans `var/exports/`, sous un jeton impossible à deviner. Une page dit où en est la tâche, puis donne le lien, valable quelques jours ; une tâche de nettoyage retire les fichiers échus.
- Avec un compte, le lien part aussi par courriel, et plus jamais de pièce jointe de plusieurs Go.
- Au-dessus d'un certain nombre de mesures (d'après `nbmesures`, sur la période demandée), un compte est nécessaire, et le lien arrive par courriel (objectif de Lou du 3 novembre).
- Une limite de fréquence par adresse IP, comme pour les liens de connexion (`config/packages/rate_limiter.yaml`).

**3. Les conditions d'utilisation.** La case à cocher du formulaire (`termsOfUses`) et sa page renvoient aux conditions de l'observatoire, qui n'existent que pour un seul. Ils cèdent la place à la Licence Ouverte Etalab, avec un rappel de citer la source : BDOH et le DOI du jeu de données, quand il y en a un.

**4. Les pages.** Les boutons de téléchargement suivent le droit (`is_granted('DOWNLOAD', …)`, déjà dans les gabarits) : ils apparaissent d'eux-mêmes. La demande d'accès (`BesoinController`) reste, pour les données fermées, et son texte le dit. Le visualiseur ne change pas. Les exports de station et de jeu de données, déjà coupés dans l'ancien (`{% if false and …`), restent coupés.

**5. Ce qui reste à vérifier dans le code, avant de commencer** : la ligne d'historique d'un export sans compte (colonne `utilisateur`), le suivi des tâches pour un anonyme, ce que la fiche Theia dit de l'accès aux données.

## Comment on le vérifie

- `compare.py` : les seuls écarts avec l'ancien sont les boutons et le formulaire, à inscrire au registre.
- Cas « nouveau seul » : sans compte, une chronique visible se télécharge, et le fichier est le même qu'avec un compte ; une chronique cachée répond 403 pour un anonyme, pour un compte sans droit, et dans une demande mêlée ; elle se télécharge avec un droit sur elle, ou avec le rôle sur l'observatoire ; un jeton inconnu ou échu répond 404 ; le seuil et la limite de fréquence se déclenchent.
- Une entrée dans `dev/differences.md`, et une relecture par un second Claude de tout chemin qui sert des valeurs.
- Pour les gestionnaires : la liste de leurs chroniques, ouvertes et fermées, par observatoire, à comparer à ce qu'ils attendent.

## Trois choix, pour Lou

1. **Le seuil au-dessus duquel un compte est demandé.** Plus il est haut, plus l'ouverture est franche, plus un anonyme peut occuper la file. Je proposerai un nombre une fois `volumes.py` passé. En attendant, ma recommandation : assez haut pour qu'aucune chronique seule n'y tombe (la plus grosse a 2,4 millions de mesures).
2. **La durée du lien.** Recommandé : 7 jours, assez pour revenir le chercher, sans garder des Go sur le disque.
3. **Les points de contrôle des chroniques visibles.** Aujourd'hui, les voir demande un droit (`canConsultCheckpoints`), et ce sont aussi des données. Recommandé : les ouvrir dans le visualiseur avec le reste, puisque seules les chroniques cachées restent fermées. Il suffit de le dire si tu les vois autrement.
